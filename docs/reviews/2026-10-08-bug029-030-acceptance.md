### [P2] BUG-031：脚注提前解码实体，字面标签仍被当 HTML 剥离

位置：2049 行。

`unescape(body)` 在脚注定义拼回整篇 HTML 之前执行。正文后续转换会再次把解码后的 `<time>` 等当标签处理，导致脚注中的字面文本静默丢失；字面 `<table>` 还可能使后面的脚注文本一起被表格处理吃掉。

最小脚注体：

```html
<p>字面 &lt;time&gt; END</p>
```

实际定义为 `[^1]: 字面  END`，应保留可见的 `<time>`。应让脚注字面文本遵循正文/表格的实体保护管线，避免提前解码后重新解释。

### [P2] BUG-032：只压缩空格，脚注内空行仍截断定义

位置：2049～2050 行。

`strip()` 只移除两端空白，`r"  +"` 只压缩普通空格。脚注正文内的换行（例如 Word `w:t` 保留的换行）仍会进入 `[^N]:` 定义。图片转换为同行 Markdown 并不能消除图片之前已有的空行。

最小脚注体：

```html
<p>Alpha&#10;&#10;Beta<img src="assets/image1.png"/></p>
```

实际定义：

```markdown
[^1]: Alpha

Beta![](assets/image1.png)
```

用 Python Markdown 的 footnotes 扩展渲染，脚注只包含 Alpha，Beta 和图片成为正文。超限跳过说明在相同位置也会脱离脚注。按本次单行策略，应归一化正文中的全部换行/空白；若保留多段落，则应输出合法缩进续行。

### [P2] BUG-033：非贪婪 li 正则在脚注内嵌套列表处提前结束

位置：2055～2057 行。

脚注体匹配在第一个 `</li>` 停止，不能区分脚注外层 li 与 Word 列表生成的内层 li。第二个列表项、后续段落及其中图片/跳过说明会留在正文，脚注正文被截断。

最小脚注体：

```html
<p>说明</p><ul><li>第一项</li><li>第二项<img src="assets/image2.png"/></li></ul><p>末尾</p>
```

实际脚注仅为 `[^1]: 说明 第一项`，第二项及图片、末尾出现在正文。应使用能跟踪嵌套深度的 HTML 解析来提取完整脚注节点，并补充列表项内图片和超限占位的回归。

以上最小输入均包在 `<ol><li id="footnote-1">…</li></ol>` 中，正文引用为 `<p>正文<sup><a href="#footnote-1">[1]</a></sup></p>`，通过 `html_to_markdown` 转换。
