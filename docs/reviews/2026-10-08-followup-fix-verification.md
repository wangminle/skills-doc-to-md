## BUG-049：零字节目录占位

根因是扫描关系目标时，`basename(name.rstrip("/"))` 对 `word/media/` 返回非空的 `media`，关系扫描把前缀扫描排除的目录重新计入图片集合。嵌套目录及非标准路径的空目录也有相同问题。

修复依据 ZIP 元数据同时检查 `is_dir()` 和 `file_size == 0`，仅将零字节目录占位从图片集合排除。带非零内容的目录名条目仍进入扫描，并由 ZIP 安全校验拒绝，保留 BUG-041/043 的防线。

提取阶段将空目录集合传入 Mammoth 回调，回调在配额检查和资源读取前将目录引用替换为“图片关系指向空目录”的可见说明。这样既不会占用真图配额，也不会经兜底分支重新生成空图片。两种资源策略均适用。

对上一份报告的更正：零字节目录在 `validate_docx_zip_security` 中会提前 `continue`，因此原缺陷**不会导致 reject 的图片数量误拒**；已复现的影响是空文件残留及 skip 配额挤占。旧记录保留历史原文，在 BUG-049 备注追加更正。

## OPT-002 / OPT-003：路径语义一致性

缺失组件不再使解析提前返回，而是作为普通组件保留，后续 `..` 仍回退，并继续解析后面的链接。单独对剩余字符串调用 `normpath` 无法处理回退后重新遇到的符号链接，因此没有采用该建议。

扩展检查另发现旧实现的固定 40 层递归上限：链接成环时会提前返回字面路径，导致 `loop/../link` 后面的正常链接未解析；60 层无环链也不能完整解析。修复前的组合检查有 53 处差异。这属于已有且原注释明确声明的降级限制，登记为 OPT-003。

最终改为待解析栈和链接目标缓存：正在解析的缓存键用于识别成环，已完整解析的链接复用结果；成环处保留字面组件后继续处理剩余路径。无需 Python 递归或固定层数上限。`_path_status` 及 `readlink` 的 `TimeoutError` 保持原样上抛。Windows 仍委托标准库。
